# RTL 工程交付与用户手工创建 CLIP

2026-09-15，总管家最新用户要求。适用于T10、T11及后续模块、同步前端和I16小工程；覆盖旧的自动生成CLIP XML/配置包要求。各任务既有算法范围、验证要求和运行授权保持。

## 只交付这三类内容

| 交付 | 用户应能直接做什么 |
|---|---|
| 完整Vivado工程 | 双击XPR，看到算法核心为Design Sources综合顶层，展开所有RTL/IP/约束；选择明确的仿真TB，定位输入和参考数据；用GUI对核心综合并导出DCP或EDIF等网表。 |
| 独立VHDL Wrapper | 明文VHDL声明并实例化该核心，逐一对应端口，必要时把宽总线拆成LabVIEW支持的宽度；独立于核心综合网表。 |
| 测试数据与中文说明 | 找到输入、对应预期输出、数据来源和有效范围；按照逐步说明在Host与Target中设置端口、传输、读取并比较结果。 |

CLIP定义、XML及LabVIEW工程由用户亲自在LabVIEW创建。Agent不再自动生成、修补或将这些配置文件列为必交项；不再以独立综合Wrapper和read_checkpoint回填为交付门槛。已有XML/旧包和失败日志原位保留为历史，新交付入口不依赖它们。

## 必须写清的使用说明

- 工程入口、正确器件xcvu11p-flgb2104-2-e、Vivado版本、唯一核心top、仿真top、源码版本和已有验证证据。Wrapper不能替代核心成为默认综合top。移动工程后所需RTL/IP/初始化数据仍可定位。
- 一张完整端口表：名称、方向、位宽、符号/定点格式、单位、所属时钟、复位值或配置值、何时有效。区分核心接口与Wrapper供LabVIEW使用的端口，给出对应关系。
- 输入和参考文件的路径、来源、长度、样点顺序、I/Q顺序、字节顺序、打包位段、缩放和溢出规则。明确哪些预期值是已验证结果，哪些仅是计划。
- 按实际硬件给出操作顺序：选择时钟→复位→设置参数→配置Host/Target传输→送数据→读结果→比较→结束或异常恢复。同步前端只喂原始波形，不让用户输入真实帧起点或参考答案。
- Host如何加载文件、组织块/DMA数据、启动传输、处理就绪/背压、持续读取结果和发现超时；Target怎样连接这些端口。没有DMA需求的小模块直接使用控件/指示器，不额外添加复杂通道。
- 成功/失败标准和一个最小可操作例子，含具体输入、关键端口值和预期输出。说明延迟、暂停、复位、输入结束如何处理，以及哪些情况会丢数或拒绝输入。

用户可手动综合；已有受授权的算法/RTL验证照常进行，不能用可打开XPR替代功能通过。未做的仿真、NI编译、实现时序或板测必须明确标未验证，不通过扩展实验来追求无关门槛。现有成功阶段不重复，运行中的冻结工程/源锁不原地修改，用户打开的GUI工程不在背后重写。
