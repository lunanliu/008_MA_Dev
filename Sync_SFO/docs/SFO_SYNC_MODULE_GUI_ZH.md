## 模块内已经包含什么

处理顺序是：原始 I/Q 和前端估计记录 → 第一次 SFO 估计 → 第一次重采样 → 第二次 SFO 估计 → 第二次重采样 → 完成两级 SFO 补偿的数据输出。

| 部分 | 工程内的内容 |
|---|---|
| 输入与记录接收 | 原始 I/Q、帧描述、粗 CFO（载波频率偏差）及精定时结果；分别按有效/就绪握手接收 |
| 第一次估计 | 真实 T06 估计器；不要求上层事先给出第一次 SFO 的正确答案 |
| 缓存与调度 | 原始数据环形缓存、中间结果 bank、访问调度、输出缓冲和已有内部跨时钟通道 |
| 两次重采样 | 当前 T10 核心中的两套重采样实例，保持已验证结构 |
| 第二次估计 | 真实 T09 残余 SFO 估计器及其 FFT 服务 |
| 输出 | 补偿后 I/Q、帧号、数据拍号、末拍标志、错误和调试信息 |

本模块不包含前端的自主帧检测与 TO/CFO 估计，也不包含后续 T11～T13 的全帧 CFO/残余 CFO 补偿。

## 与同步前端怎样连接

两块模块的 I/Q 格式相容：每拍 4 个复数样点，每点用 32 位保存，低 16 位为 I、高 16 位为 Q。但目前尚未交付把两个模块直接连起来的联合顶层。

1. **先保留原始波形。** 同步前端输出检测和估计结果，没有完整帧 I/Q 输出。上层应保存原始采样，例如写入 DDR，再按前端给出的帧位置回放所需帧及保护样点到本 SFO 模块。前端的小范围历史缓存不能代替整帧数据来源；T10 内部缓存负责已送入本模块的数据存取。
2. **转换估计记录。** 前端 `cfo_hz` 与 SFO Wrapper 的 `cfo_value_hz` 都使用有符号 Hz；但前端的联合结果必须转成 T10 分开的 CFO、精定时与帧描述握手记录，帧号需一致。状态/质量字段按各自接口定义转换，不能把整个记录直接复制。
3. **统一坐标和地址。** 前端 `fine_absolute` 是连续采样段中的 64 位坐标；T10 接收帧内约定的 32 位有符号坐标。`frame_raw_first_word` 是 T10 内部的 128 位数据拍地址，不是 DDR 地址。帧号、generation、名义原点和相位初值也需由上层按接口约定提供。
4. **按实际时钟连接。** 输入和配置使用 125 MHz，重采样及当前输出使用 150 MHz，FFT 服务使用 500 MHz。Wrapper 只做端口拼接与拆分，没有 MMCM/PLL，也没有新增平台 FIFO 或跨域适配。上层时钟派生、锁定复位和 DDR/DMA 跨域连接仍需在集成时落实。

这些连接要求不妨碍现在对独立 SFO 模块进行 GUI 综合和已知数据测试，但不能据此宣称“同步前端加 SFO”的整链已经验证。

## 在 Vivado 中怎么开始

完整复制 `Sync_SFO` 模块文件夹，保留内部相对目录。双击上述 XPR，确认核心顶层、器件和 `OUTPUT_CLOCK_MHZ=150`。按手工操作说明检查 IP 状态，需要时从已有 XCI 生成 IP 输出。

核心将被上层实例化，综合按说明选择 `-mode out_of_context`，然后由用户点击 Run Synthesis。综合完成后打开综合设计，检查错误和未解析黑盒，再导出 DCP；具体导出命令已在手工操作说明中给出。本次没有代为运行综合、生成网表、CLIP XML 或 LabVIEW 工程。

## 已经通过与还没有验证的内容

已通过既定 case6001 的完整帧行为验证：无噪声单径、SFO −150 ppm、CFO +100 kHz，输出 1,336,320 个复数样点；与冻结有限字长参考比较，8,321,168 个 I/Q 分量的最大差为 0 LSB。LSB 指量化数据的最低一位。这是该用例的功能证据。

当前工程和外围 VHDL 的静态接口核对已完成。正确 FLGB 器件上的实现时序、连续多帧吞吐、NI 编译/网表绑定以及板测需分别确认，不能从完整帧行为仿真通过推导出来。
