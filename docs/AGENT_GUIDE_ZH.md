# Agent开工指南

## 先选对文件

从README进入项目书及迁移记录。硬件top为t10_two_pass_system，仿真top为t10_full023_tb；只使用工程清单，不从旧目录或历史报告中按同名拼装。IP配置、系数、约束、参考输入和检查器也属于版本的一部分。

## 工具调用

- 常规工程操作使用Vivado GUI或同一项目的原生Tcl。先确认当前解释器是Vivado Tcl还是XSim Tcl，不能假定所有命令通用。
- Python只用于明确的离线分析或身份核查，调用独立解释器完整路径。进入Vivado环境后，避免继承PYTHONHOME/PYTHONPATH造成解释器与库混用；不要修改全局环境修补局部问题。
- PowerShell、Tcl和Python的参数边界分别处理，避免多层拼接引号。路径由项目位置推导，不依赖某台电脑的用户缓存目录。
- 仿真先检查输入文件存在、样本数、首尾值和未知态。`readmemh`失败首先检查实际路径和仿真工作目录。

## 结果与失败

- 进程存活、模拟时间、已处理样本数、验收通过是四件不同的事。CPU忙和exit 0都不能代替结果判断。
- 保存第一处故障的模拟时间、帧/采样编号、实际值和参考值。未知厂商IP错误不能直接屏蔽；已审查的良性诊断也必须满足原证据条件。
- 日志可能尚未写完整；读到半行不能判整份记录损坏。可选显示文件失败不应直接抹掉已成功的计算。
- 原始结果和可选报告分开。报告生成、通知或交接失败只修复对应阶段，不能重复已成功的长仿真。
- 仅操作自己所属的进程树，不按进程名批量结束其它任务。关闭启动脚本不等于所有子进程都退出。

## 交接与版本

本任务Luna自行解决命令、路径、环境和包装问题。需要改变RTL运算、算法、输入含义或验收条件时交Astra复核。用户设置的模型、推理强度、速度不自行更改。

每次原生运行有独立目录、输入指纹、预算和硬超时。正常工作每15分钟报告；空闲不为报告反复唤醒。修改先查Git，提交前核对实际差异；不自动更新指纹来掩盖文件变化。

当前独立工程不含CLIP。正确器件为xcvu11p-flgb2104-2-e；旧FLGC网表、缓存和时序报告不能变成新器件的通过证据。
