# 本地Git：保存和检查你的修改

仓库根目录就是本项目根目录。Git的历史存储在隐藏的`.git`目录中。本项目没有配置云端remote，使用commit即可建立本地版本，不需要push。

## 日常使用

在本项目目录打开终端：

```powershell
git status --short --branch
git diff
git log --oneline -5
```

第一条看哪些文件改变；第二条看具体文本变化；第三条看最近保存的版本。Vivado生成缓存、WDB和运行目录被忽略；源码、测试数据、文档和必要项目配置才进入版本。

一次改动检查完成后，明确选择相关文件：

```powershell
git add rtl/t10/某个实际文件.sv docs/相关说明.md
git diff --cached
git commit -m "说明本次改了什么以及为什么"
```

示例中的文件名需要换成实际名称。避免习惯性把整个目录所有新文件都加入，以免误收大型临时产物。不要用reset --hard或clean来“解决”不理解的Git状态。

想查看旧版本而不覆盖当前文件，可以使用 `git show 提交号:相对文件路径`。需要较大修改时可新建 `codex/说明用途` 分支，保留main上的基线。

## 为什么参考数据也保存

本地可重现测试需要冻结输入和参考答案。已选择的MEM/MAT属于输入，和随时可以重生成的仿真缓存不同。它们可能比较大，但本次本地仓库明确保存这些必要文件，不依赖云端LFS或外部下载才能读取。

`.gitattributes`关闭隐式换行转换，以保持复制来源的字节和指纹；文本仍可正常查看差异。未来如需要统一换行，应单独提交并明确说明。

## 版本管理能证明什么

提交成功证明这组文件可以被Git保存和读取，不证明RTL正确。本次验证还检查仓库完整性、提交中的关键文件内容和工作区状态。若要复制到另一台电脑并保留历史，连同隐藏的`.git`一起复制，或使用Git本地clone；只复制Vivado归档不会自动携带Git历史。
