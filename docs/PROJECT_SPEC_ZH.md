# 项目书：两次SFO估计与重采样

## 1. 这个模块解决什么问题

发送机和接收机的采样时钟通常不会完全一致。假设发送机每秒采样500,000,000次，而接收机略快或略慢，时间越长，接收样本对应的位置就偏得越远。这种偏差称为**采样频率偏差（SFO，Sampling Frequency Offset）**。

偏差常用ppm表示，1 ppm等于百万分之一。例如100 ppm描述相对时钟差，不是固定移动100个样本。补偿方法是先估计偏差，再通过插值计算正确位置处的样本，这个过程叫**重采样**。

本工程先利用帧开头已知训练符号做一次估计和补偿，再利用分布在整帧的已知导频做更精细的估计和第二次补偿。两次处理是为了逐步减小残余误差。

## 2. 输入与输出的范围

硬件顶层为 `t10_two_pass_system`。输入是前级已经变成复数基带的数字I/Q采样，不是射频ADC原始电压。一个复数点由16位有符号I和16位有符号Q组成，一拍输入4点，共128位。

| 外部提供什么 | 作用 |
|---|---|
| 原始整帧I/Q及帧前、帧后邻接样本 | 提供实际待校正数据，并满足插值滤波边界读取 |
| 帧编号、采样坐标、帧描述符 | 让数据和估计结果属于同一帧，确定读取位置 |
| 粗CFO估计记录 | 提供粗略载波频偏，供训练数据支路做局部相位校正 |
| 精定时记录 | 提供该帧准确起始位置 |
| 三路时钟和复位/取消控制 | 驱动模块内部不同速率的处理单元 |
| 输出ready | 表明下游现在能否接收输出 |

输出是第二次SFO重采样后的整帧I/Q和标识信息。**本模块不产生上游粗CFO和精定时记录**；当前测试台给出这些边界输入。因此，打开此工程能看到T10内部依赖，但不代表T04/T05整个接收前端已经接入。

接口的准确打包如下，可结合公共SystemVerilog类型阅读：

| 信号 | 位宽与顺序 |
|---|---|
| `s_data` | 128位；最低32位为最早样点，每个样点为高16位Q、低16位I |
| `frame_record` | 188位；从高到低为帧号32、生成编号32、原始首字地址64、名义原点32、Q28初始相位28 |
| `cfo_record`、`fine_record` | 各96位；从高到低为值32、质量16、状态16、帧号32 |
| `m_record` | 225位；从高到低为帧号32、生成编号32、拍号32、末拍标志1、数据128 |

当前输入要求4路全部有效。debug125/debug150及E1观察端口用于只读诊断，各自有时钟域，不能在另一时钟域直接拼成所谓“同步快照”。

**CFO（Carrier Frequency Offset，载波频率偏差）**使复数信号不断旋转；其补偿通常是复数相位旋转。它与改变采样位置的SFO补偿不同。本工程仅在训练支路局部补偿粗CFO，不包含后续整帧CFO算法和LabVIEW/CLIP集成。

## 3. 数据实际如何走

1. 原始输入进入后分成两路：一路保存到原始帧缓存R0；另一路由T06读取训练区域。
2. T06根据精定时找到Preamble 3到10这8个训练符号。每个符号去掉512点循环前缀后，使用2048个有效点，合计16,384个复数点。循环前缀是符号前面复制的一小段数据，用来帮助抵抗传播延迟。
3. T06先对训练数据做局部粗CFO校正，再进行FFT和第一次SFO估计。FFT是快速傅里叶变换，用来得到各子载波的数据。
4. 第一次重采样器E1使用估计结果，从R0重新取样，生成第一次补偿帧R1。它要等所需原始窗口完整、记录匹配，才开始相应处理。
5. R1完整发布后，T09读取散布在帧内的74个窗口，利用导频估计剩余SFO。导频就是收发双方预先知道取值的子载波，便于测量失真。
6. 第二次重采样器E2按照T09估计结果重新取样R1，输出名义长度的帧。

E1和E2是两套处理实例。即使它们复用同类计算设计，实际实例、数据读取和缓存关系仍需按当前顶层检查，不能假定只用一套硬件就能保持相同吞吐量。

## 4. 为什么要额外的边界样本

插值滤波器计算一个输出点时，需要读取它附近的一组输入点。帧的第一个和最后一个输出也一样，所以只给名义帧内数据可能不够。

| 数据对象 | 复数点数 | 相对名义帧原点的范围 |
|---|---:|---|
| 名义帧 | 1,336,320 | 0至N−1 |
| 原始输入及邻接样本 | N＋540＝1,336,860 | −172至N＋367 |
| 第一次重采样输出R1 | N＋72＝1,336,392 | −36至N＋35 |
| 第二次重采样输出 | N＝1,336,320 | 0至N−1 |

这些邻接样本是滤波所需的真实上下文，不能随意补零，也不能把帧编号不同的数据无条件拼接。它们不自动意味着“跨帧干扰已经解决”；边界定义、读地址和信号生成方式需要一致。

## 5. 时钟与握手

| 时钟 | 主要工作 | 本工程的边界 |
|---|---|---|
| 125 MHz | 输入、记录控制、T06/T09部分控制与计算 | 输入每拍4点，名义500 MS/s |
| 150 MHz | 两次重采样、相关缓存调度、默认输出 | 输出接口有背压；4点/拍只是峰值接口能力 |
| 500 MHz | FFT/IFFT高速服务内部处理 | 通过跨时钟机制连接较慢控制侧 |

MS/s表示每秒百万个样本。125 MHz乘4点等于500 MS/s，是接口容量计算；要证明持续工作不丢数据，还必须检查停顿、缓存占用和跨帧调度。

独立顶层接收三路时钟，本轮不把CLIP的时钟包装带进来。仿真时测试台产生这些时钟；将来连接真实平台时，需要结合平台时钟资源、复位和约束另行集成。

当前启用三个根时钟声明；旧核心跨域时序约束原文已保存在`constraints/reference_synth016`，尚未作为新FLGB物理验收约束启用，具体见[约束说明](../constraints/README_ZH.md)。

`valid`表示发送方有一个有效数据，`ready`表示接收方能接收。只有同一拍两者都为1才完成一次传输。接收方拉低ready叫**背压**；发送方必须保持未被接收的数据，不能偷偷前进。不同频率的时钟之间使用跨时钟通信（CDC），不能把多位数据直接接过去假定同步。

## 6. 这次带入的测试用例

冻结完整帧用例为frame6001：无噪声、单径、注入SFO −150 ppm，粗CFO边界记录为＋100,000 Hz，精定时为0。输入与参考来自原来同一个场景；迁移不重新生成它们。

| 文件/结果 | 用途 |
|---|---|
| raw.mem | 实际送入RTL的原始采样 |
| r1.mem、r2.mem | 第一次、第二次重采样的参考答案 |
| delay.mem、delta.mem | 第二次估计的点级和最终比较参考 |
| t09_pilot_phase.mem | RTL使用的导频相位只读表 |
| data/events/points/xpm_trace输出 | 记录实际传输、事件、估计点和FIFO诊断 |

参考文件只供比较；T06/T09的估计值必须由真实RTL计算。不能把参考值塞进估计接口后声称整链通过。

波形源、MATLAB脚本和数值格式见[参考数据指南](MATLAB_REFERENCE_GUIDE_ZH.md)。当前完整帧用例不是短测试；用于开工检查的0ns打开或短前缀也不能代替完整帧结果。

## 7. 如何判断测试结果

| 检查层次 | 需要的证据 |
|---|---|
| 文件迁移 | 每个输入/源码的来源、指纹及已声明的路径修改；没有漏拷或重复模块 |
| 工程创建 | 正确part、准确源集、顶层、IP状态和约束；工程可重新打开 |
| 行为仿真 | 数据确实加载；估计来自RTL；逐点误差、计数、帧标识和因果顺序满足对应测试条件 |
| 综合/实现 | 正确FLGB器件下的新资源、时序、DRC及CDC结果；旧FLGC报告仅为历史 |
| 持续吞吐 | 连续多帧无丢失/重复/错序，缓存有界，服务时间满足供数压力 |

当前完整帧测试沿用逐I/Q分量不超过1 LSB的比较要求；LSB是数字定点数最低位代表的最小量化步长。还要检查74个估计窗口、最终输出334,080拍以及故障标志。具体判断以已冻结测试台和检查器为准，不因迁移放宽。

EVM是归一化均方误差的一种表达，用来概括波形误差；它不能代替逐点、接口和数据完整性检查。重采样研究中用户批准FFT有效窗口内EVM低于−45 dB，全时域EVM仍报告但不采用相同硬门槛；这不自动改变完整RTL测试原有的逐点门槛。
