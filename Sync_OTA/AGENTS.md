# Sync OTA 执行规则

1. 本轮用户已授权完整系统集成、必要短验证、核心综合和手工上板交付；以docs/PROJECT_SPEC_ZH.md为任务书，优先于父目录旧T10/三模块整理范围。
2. 仅修改Sync_OTA，不改Sync_Frontend、Sync_SFO、Sync_CFO或旧工程。按完整版本复制必要源并锁定身份，禁止递归混选同名文件。
3. 固定本任务Astra/Luna一对一。Astra设计与复核；Luna执行与自修命令、路径、私有环境问题。模型由用户控制，Standard禁Fast，普通消息省略配置覆盖。
4. 正式核心top为sync_ota_top；真实完整算法进入综合。测试替身仅存在于明确命名的仿真源集；不以参考真值代替RTL估计。
5. 首先冻结存储生命周期、帧描述符、数据版本和时钟/CDC合同。只做覆盖新增风险的短测试，不重跑旧全帧长仿真或广泛扫参。
6. 原生作业先冻结source set/输入/命令/预算/保护/输出目录，再取得总管家具体槽授权；全机2 Vivado/1 MATLAB、每对1 Vivado。general/synth8，jobs/xelab上限16，按总资源合理使用。
7. 工作期每15分钟按总管家表格报告，空闲停表。派单后Astra结束轮次，Luna负责监控；只重跑失败或受改动影响的阶段。
8. 交付核心XPR/综合网表、独立VHDL Wrapper和完整端口/上板数据说明；不生成CLIP XML/NI工程。工程打开、短测、综合时序、布线时序、持续吞吐、板测分别标状态。
9. 本地Git只提交本任务文件，保留用户分支与其他修改。原始/失败证据保留，不改全局环境，不批量kill进程。
