# CFO数据流、全系统缓存寿命与吞吐边界

2026-09-14架构审查。批准模型主配置与历史数值结论不变。本表依据已复制到docs/provenance/T10_memory_sources的当前T10源码；这些副本只读分析，不属于CFO编译源。历史资源总量只作规划输入，FLGB实际综合、布局布线尚未验证。

## 数据和算术边界

T10第二次SFO输出 → 按实际两级SFO坐标做粗CFO旋转 → **第一次独立RNE/S16饱和** → 保存整帧并抽取74个导频符号 → FFT2048及导频相关 → 74点相位/FFT256质量门与相位OLS → residual CFO参数 → 重读整帧、最终旋转 → **第二次独立RNE/S16饱和** → 输出。

不能将两次旋转合并，不能让后级读取未量化的粗旋转中间数，不能以参考答案驱动应由RTL估计的residual CFO。两级旋转可各4路、独立工作，ROM端口与定点量化都必须分别计入。

T10现有225bit数据记录：frame32、generation32、beat32、last1、4×{Q16,I16}。配置还需要与同一frame/generation绑定的实际第一/第二SFO步长Q28、raw_origin、粗CFO Hz及最终输出坐标原点；不能用名义ppm替代实际量化步长，不能把调试寄存器瞬时值当作稳定描述符。目前补偿核只接受phase0/step字，完整坐标控制器仍待实现；不擅改T10接口。

## 现有缓存不能随意借用

| 区域 | 物理深度/容量 | 所有者及数据寿命 | 最后读取和释放 | 端口/重叠规则 |
|---|---|---|---|---|
| T10 raw ring | 393216×128bit，192 URAM规划 | 原始样本从接收直至E1读取；环可能跨帧边界 | 已发出读取但仍保留256beat，另有命令/读响应和FIFO信用 | 150 MHz单读单写；只回收已被读取协议保障的地址 |
| R1 bank A | 335872×128bit，164 URAM规划 | E1写完发布；T09稀疏读74符号；E2顺序读 | E2开始时取消旧committed；新E1写必须严格落后旧E2 issued-read frontier | 单读单写；旧帧尾与新帧头可共处；不是空闲整帧bank |
| R1 bank B | 同A | 与A轮换；另一帧可做T09/E1 | 同A；T09须先结束，顺序读取方已保留响应空间 | 同A；单E2，不能假定两bank可同时被CFO长借 |
| T10 output ring | 65536×128bit，32 URAM规划 | E2结果直至下游真实接受 | 下游握手释放，FIFO响应仍需保留信用 | 峰值4sample/150 MHz；约0.196帧，不能存整帧 |
| CFO粗补偿帧区（本次候选） | 335872×128bit，96 URAM+544 RAMB36规划 | 粗旋转后S16旧帧供估计/最终输出；新帧只覆写已释放区域 | 旧帧最后读取的数据已捕获且为下游保留空间，才能推进释放前沿 | 单读单写；旧尾/新头双generation描述符，严格防同址未捕获覆写 |
| CFO估计工作区（待细化） | FFT窗口、74个相关z、FFT256等小区 | 粗量化流抽取→FFT/相位处理→完成参数 | 参数锁定后工作区可转下一帧 | 需逐模块确定BRAM/DSP/端口；不另存全帧DDP矩阵 |
| 所有流水、跨时钟与弹性FIFO | 不包含在上面帧区容量中 | 已发读请求、未返回响应、被背压输出 | 必须以独立inflight信用计数释放 | 不能凭上游issued就假定下游已接受 |

五个帧存储区的逻辑128bit容量上界为1,466,368beat、23,461,888byte；不包括小工作区和在途队列。raw环在跨边界情形可含至多3个帧片段；两R1合计可含至多3个版本（一个旧E2尾/新E1头加另一bank）；output环可跨2帧；CFO环最多旧/新2版本。这些是各区局部保守上界，不能把相加的10个片段标签解释成10个完整帧，也尚未证明它们能在同一时刻同时达到。

## CFO单帧区候选的资源分配

旧T10规划合计552 URAM，BRAM36等效218.5。直接再加双CFO整帧区需328 URAM，合计880，超过672硬限，已经否决。

本候选使用单个可逐地址回收的整帧区：

- 96 URAM：48组4096×128bit（每组2个72bit URAM），覆盖196608beat。
- 剩余139264beat：136组1024×128bit，每组4个RAMB36，共544 RAMB36。
- 总帧区335872beat，实际一帧334080beat，余1792beat。
- 与旧T10规划相加为648 URAM、762.5 RAMB36等效，距硬上限672/1411尚有24 URAM、648.5 RAMB36等效供估计器、ROM、FIFO及实现变化。

这是端口和存储几何的可行候选，不是综合结果。URAM已高于60%目标576、低于70%硬限672；仍保留项目30%NI空间要求的原口径，不声称NI集成已验证。后续须实测ROM/DSP映射、分段寻址MUX、RAM碰撞模式及150 MHz时序。缓存实现可优先使用固定原语/XPM几何，禁止用未约束的大行为数组掩盖容量。

## 读写并行日程

1. 帧n的粗旋转流写入CFO环并同步提取74个导频相关量。直到最后必要样本到达，才完成n的residual估计。
2. 参数锁定后，最终旋转连续读取n。被捕获且信用已保留的每个旧地址可释放给n+1粗旋转写入。两次S16量化仍分开。
3. n+1写不能越过n释放前沿；阻塞须通过ready回传T10 output ring。旧帧读完、下一帧完全提交且参数有效后，才切换下一读generation。
4. INVALID/取消/复位必须释放相应generation的所有队列；不能将后一个帧的估计参数用于旧帧。丢弃策略和输出状态随完整控制器再冻结。

## 吞吐还缺什么证明

4×150 MHz是600 MS/s瞬时算术能力，不是500 MS/s持续服务证明。若每帧估计尾延迟G≤30000cycle、额外下游停顿S≤20000cycle，则仅该CFO读出服务为334080+G+S=384080cycle/帧，约521.9 MS/s；还需计配置间隙、FFT争用和所有额外停顿。

既有65536beat output ring只有在入口初始占用+在途预留≤15536beat、对应突发和读写日程成立时，才足以吸收50000beat缺口。500 MS/s的长期平均值不能限制T10 E2的600 MS/s连续突发长度。现有R1允许追随覆写，会改变多帧到达形状，必须对全系统arrival envelope、逐地址释放、raw占用及背压传播给出证明并用计数验证。

因此当前可以继续实现已冻结算术模块，但整体缓存/持续吞吐尚未PASS。验收至少记录每区最大占用、每个generation的最后读/首覆写、读写冲突、inflight上界、实际接受样本/周期、服务缺口、丢/重/乱序以及输出最慢服务约束。若候选不满足该边界，应在资源预算内调整弹性缓存/调度并重新冻结受影响部分，不重复SFO实验、不默认新增两个整帧缓存。
