## 方案比较

方案 A：将宽乘法拆为 DSP 部分积与寄存加法树。延迟较短，但每个不同宽度需要明确 DSP 级联布局，多组低占空比运算常驻资源较多。方案 B：六个仅在帧尾使用的乘法共用 98 位无符号移位加法器，每拍至多一次本地 98 位进位链，操作数先寄存。选择 B；每帧额外约 160 个 clk125 远小于整帧和尾部预算，并保持全部整数精度。24×24 点平方及 9×24 点权重按原拍保留。

除法方案 A：最后除法迭代、RNE判据、81位加一分别寄存；方案 B：直接重写商/余数与RNE的组合表达以尝试共享进位。选择 A，每次多2拍，busy覆盖整个尾部，不改变80轮除法或ties-to-even定义。

迭代保持 A_r + (B_r×C_r)=原乘积（按尚未处理低位的标准移位加法不变量）；最后一轮采纳新和而非旧累加器。abs(-2^39)保留在unsigned40，abs(-2^40)保留在unsigned41；不得把它们作为有符号乘数。98位覆盖所有最大乘积；写入80/61位目的寄存器时高位必为零。SSE仍先零扩展各98位非负项到signed100再两次相减。

RNE判据为2R>D或2R==D且Q最低位为1；最终除法轮先保存完整Q/R，下一拍保存判据，再下一拍输出81位Q+判据。m_valid保持到m_ready；busy在发布前始终为1；除零、reset、abort沿现有合同处理，不在尾部提前接受新请求。
