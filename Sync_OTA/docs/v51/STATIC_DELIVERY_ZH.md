本轮关闭的问题包括：raw 满环与终端 floor 互等、读响应尚未消费就释放 bank 的风险、训练/窗口/COMMIT 身份与顺序、跨帧窗口信用、尾拍和成功通知竞争、故障组合反馈、候选编号回绕排序，以及若干实际长组合算术链。每处设计的至少两种方案和选择理由见 [总体设计记录](REFACTOR_DESIGN_ZH.md)。

SFO LS 帧尾采用全精度共享串乘，除法舍入分拍；最后窗至结果净增 157 个 clk125，74 个 peak 各增加两拍已进入逐窗预算。CFO 动态移位、功率累计、规范化、舍入分拍，帧尾低频宽乘法采用串行移位加法；主导后端尾部增加 259 个 clk150，即约 1.727 微秒。增加的是局部处理延迟，目的是缩短组合路径，不是宣称提速；多帧吞吐另由下表证明。两组具体位宽、事件和备选见 [SFO 算术设计](SFO_ARITHMETIC_STATIC_CHANGE_ZH.md)、[CFO 算术设计](CFO_PIPELINE_STATIC_CHANGE_ZH.md)。半带 FIR 重写、FFT 替换、CFO 直接投影均未引入。

## 服务合同与每帧周期表

名义帧为 1336320 复样点，即 522×(2048+512)，334080 个四点字，2.67264 ms。连续合法帧预算采用物理 SFO 在 ±150 ppm、每个真实帧至多一次成功确认、没有额外无界 TO 漂移的输入合同：raw 帧距至少 334029 字，保守周期 **400834 clk150**。估计器的数值范围本身不证明实际输入满足该合同；超密假确认不属于无损持续服务承诺。

厂商合同采用实际四 FIR 的固定 II=1 弹性服务与延迟 18/10/14/30，总 Lfir=72，四个输入 FIFO 另计 64 拍。安装版 Vivado 2021.1 静态函数给出 main FFT 核延迟 6287 clk500、aux 在本路径 runtime NFFT=11 时为 6306 clk500；aux 名称中的16384是最大点数。FFT 为 Realtime/no CP，无输出或状态 TREADY。

计入输入/输出各2048拍及64拍接口边界容差，FFT 服务合同 Xm=10447、Xa=10466 clk500，小于设计要求10512/12392；64拍是明确的合同容差，并非加密内部穷尽证明或实测。首次数据前必须配置完成，未宣称首次 config-ready 的绝对最大等待。接口依据为 [PG109](https://www.amd.com/content/dam/xilinx/support/documents/ip_documentation/xfft/v9_1/pg109-xfft.pdf) 和 [PG149 latency](https://docs.amd.com/r/en-US/pg149-fir-compiler/Latency)、[ready/valid](https://docs.amd.com/r/en-US/pg149-fir-compiler/TREADY-and-TVALID)。公开文档版本晚于安装版；精确延迟数字来自本地工具，不混称同版本证据。
