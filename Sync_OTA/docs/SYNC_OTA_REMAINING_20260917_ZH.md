# Sync OTA 设计复盘、整改与剩余隐患

更新：2026-09-17。用户已批准静态复盘及范围内设计整改，测试仍暂停。本轮不启动仿真、综合、实现、MATLAB、板测或测试脚本。原 Astra / 唯一 Luna 配对；Astra修改设计与统一工程，Luna独立只读审查。本文集中维护预算、设计决定和残余问题，不拆成一组小工程或零碎报告。

## 1. 设计基线与交付边界

唯一 GUI 入口为根目录 Sync_OTA.xpr，综合顶层 sync_ota_top，器件 xcvu11p-flgb2104-2-e，Vivado 2021.1。保持 rtl/frontend、sfo、cfo、buffer、control、common 的功能分区及原实例层级。原始 A06 文件与锁定证据不改；仅受影响的完整模块在同目录保存 A07 修订，保留模块名/端口，生产 XPR 和一份 sources_a07.f 选择新版本，旧版本不同时编入。不新建子工程，不把算法顶层换成 Wrapper。

旧 A06R1 完整核心综合是历史证据：clk125 WNS +2.410 ns，clk150 −2.358 ns，clk500 −1.279 ns；不是 A07 的时序结论。A06R3完整资料已经成功回传，Gray 24宏及116条报告路径已离线核验，原零critical总闸失败、原生警告和182条CDC Warning保留。修改后的 RTL 本轮只作设计审查。

## 2. 修改 RTL 前的指标、每拍预算与架构决定

|---|---|---|

| 150 MHz | 6.666666667 ns；两级SFO重采样、CFO控制/旋转、后端 | 每拍4样点只表示600 MS/s端口峰值。拆掉“相位/FFT频率→乘比较→模式→错误→ready→SFO BRAM使能”的跨模块长链；完整结果寄存，CFO输入增加真实2槽弹性容量，上游ready仅由本地寄存状态/占用给出 |
| 500 MHz | 2 ns；FFT及导频处理 | 已知路径为FFT索引→减法→系数基址加法/DSP→ROM使能。拟分成索引译码寄存、地址加法寄存、ROM读三拍；IQ/index/valid同行，算法乘法/舍入/求和顺序不改。新增两拍延迟，不降低接收II |

150 MHz后端一致性判定的两态整数证明：signed32频率差在signed64中计算，绝对差最大4294967295；乘4587520的最大值19703248365158400小于2^64；32768000000000 = 7142857×4587520 + 655360。因此原比较严格等价于 abs_difference <= 7142857，保留等号、不改变算法阈值。复位/abort清有效位，未知值不作合法输入承诺。

后端两个计算核心只在联合结果可写入寄存器时同时消费；寄存结果在m_valid且下游未ready时全部保持。结果寄存器无需同拍消费重填：每次需74条观测，隔一拍重新接纳结果不形成样点吞吐瓶颈。帧号、generation、错误、模式、有效性、频率和所有质量记录必须一起寄存。

CFO入口弹性缓冲为2条完整225位记录，包含frame/generation/beat/last/IQ；计数0..2，空不读、满不写，同时读写保持计数并移动队列。禁止仅给ready打一拍而没有额外存储。上游允许在下游刚停住时把余下信用写入队列，错误/取消后整帧作废，缓冲随本地停止清空；不得把已取消的记录送入下一帧。复位/取消最高优先，其次失败，再正常接收/输出。

500 MHz新级只有valid需要复位；过期数据本体不必复位。错窗或abort同时冲掉地址级和原六级valid；sum_done与fft_done仍须同时成立后才发布结果。窗口基址在该窗第一拍输入锁定，直到结果交付前不更新。ROM地址范围0..60679，pilot索引0..819，74×820=60680，分拍不改变系数映射。

## 3. 持续吞吐与存储生命周期：先算能不能工作

当前调度是单会话、有限帧离线链路：捕获封存→扫描检测→原始窗口装入SFO→两级重采样→粗CFO帧写回→74窗口估计→最终回读旋转→Host消费后释放。处理期间不能接收下一原始帧，因此架构本身不满足无间断500 MS/s。这是状态机与带宽结论，不是待仿真才能判断的风险。

设捕获C个128位字。每会话DDR访问量为：原始写16C，当前前端扫描DDR读16C（命中后停止喂前端，但controller仍排空整段DDR回放），SFO原始回放5347440字节，粗CFO写5345280字节，74×512窗口读606208字节，最终帧读5345280字节。当前固定处理流程合计32C+16644208字节；以最低可覆盖保护样点的C=334215举例为27339088字节。1336320样点按500 MS/s仅有2.67264 ms帧间隔，对应约10.229 GB/s的聚合访问需求；现有128位×125 MHz物理事务口即使每拍接受一字也只有2 GB/s峰值，理想搬运下界13.670 ms，尚未计单信用、CDC和算法等待。此例是设计预算，不能当成实测速率。

单信用store每次必须等待匹配tag响应才能继续；令命令在t0边沿接受、合法响应在tL边沿接受（L>=1）：WRITE_WAIT在tL返回CAPTURE，下一写最早t(L+1)；读则在tL进入OUTPUT_WORD、t(L+1)消费、t(L+2)才发下一命令。因此本地连续命令间隔下界为写L+1、读L+2拍。旧合同的L+2/L+3未明确边沿口径，本轮按源码澄清，旧冻结文件不改。NI桥、CDC、仲裁和背压还会增加等待。若外部响应无最大延迟，端到端最坏完成时间没有有限上界。Host必须遵守ready，连续ADC源需另有可靠采集缓存/丢帧策略，不能直接无背压接入本核心。

|---|---|---|
| RAW DDR | capture→frontend/SFO replay；建议524288×128=8 MiB | 所有写ACK才封存；最后raw读者已接受末字且信用清零后才能改为粗CFO区域；不把raw和coarse容量简单相加 |

连续流若成为下一交付门槛，需先改变架构：采集与处理双会话所有权、按实际NI带宽减少重复DDR遍历/采用流式分块，具有明确最大服务空隙的多信用/突发适配、各阶段服务率和帧周转预算同时满足。仅增加并行lane或2槽buffer不能解决约5倍以上的访问带宽差。本轮不擅自替换NI事务接口或声称已完成连续流重构。

## 4. 整体审查范围和剩余项

主审覆盖统一XPR/选源、顶层阶段调度和描述符、缓冲所有权/DDR、两级SFO传输与配置范围、CFO旋转/坐标/观测后端、关键FFT/ROM路径及CDC复位。复用算法内核继承既有合同和证据，审查不等于逐一重新证明全部数值实现。Luna独立审查buffer/control/common及顶层；其可读回执先接收，缺项单独补充，不以格式差异否认整份结果。

已有合法范围约束：SFO1 ±150 ppm、SFO2 ±3 ppm；两级步长都接近2^28，不能将仅检查非零的通用CFO坐标核推广为任意step合法。坐标宽度/舍入须按此组合范围解释，异常身份必须停止整帧。两次CFO的S16舍入饱和仍分别发生，不合并为一次旋转。

CDC多位数据/描述符走原子FIFO，状态位跨域仅允许稳定/粘滞单bit；算法复位与DDR事务取消排空分开。硬复位需要NI同时撤销旧信用，不能在NI仍会返回旧tag时单边清零序列。FIFO释放等待双方busy握手。取消、最后响应、最后数据、完成消费同时发生的优先级正由独立审查复核。

本轮已将设计落实到六个受影响的完整模块与唯一根XPR；Astra逐条静态复核新增流水/缓冲状态转移、有效位清除、数据对齐与源集，Luna作独立复审。剩余CDC警告分类、150/500MHz物理时序、NI DDR最坏服务延迟、外部时钟关系、持续流架构及真实板级吞吐仍需明确列出；未经新授权不运行验证。

## 5. 修改中复审新增：会话恢复与取消优先级

静态反例：ota_frame_store将error_code保留到下一次start握手。上一租约返回带error的匹配响应后，cancel排空可以回到IDLE，但error仍非零。上层接受新start/context后进入OPEN；同一拍store将接受start并清旧error，而上层仍读取旧值，错误转移到CANCEL_DRAIN/FAIL，新会话被旧诊断误杀。整改决定：raw和CFO控制器仅在OPEN阶段隔离上一租约的mem_error；完成start握手进入CAPTURE/COARSE_COORD后恢复监测。新start参数非法/代数耗尽产生的错误下一拍仍被捕获，不能忽略整个后续处理阶段。旧错误仍保留到真实新start，不以取消直接抹掉诊断。

CFO FIFO错误是粘滞诊断，清除点为下一正式context；原顶层将其无条件并入algorithm_fault，可能使下一会话在到达context前就又被取消。整改决定：其停止作用只在cfo_busy150期间有效，闲置时保留诊断可读；新context握手同时清旧FIFO记录并进入OPEN，避免跨帧误触发。桥的协议错误仍单独保持并阻止start，必须由NI与RTL协调平台复位，不能在未排空事务时私自解锁。

另外，顶层捕获控制器的start_ready补充!cancel：cancel和start同沿时不接受新会话。取消与匹配响应同沿可以归还信用但丢弃其数据；错误/取消帧不保留有效数据承诺。以上决定在修改控制器前写入本节，并交唯一Luna独立复核。


## 6. 独立审查回执接收与追加整改设计

唯一Luna已回传中间静态审查；整份先接收，再按当前版本校对中途源集快照，不因快照或格式差异阻断成果。旧lease错误与DDR边沿预算得到独立确认。新增两项明确整改：

1. DDR bridge的idle125在SELECT且raw_cmd_valid=1时仍可能为1。虽然现顶层还检查mem_busy，独立使用此诊断会提前判断空闲。增加!raw_cmd_valid，idle表示本125域已观察到的请求/响应队列与事务均空；跨域尚在传播的请求仍须与上层busy/握手共同判断，不能把单个域的空标志当全系统栅栏。
2. bridge只汇总125域req_under/rsp_over，未汇总150域req_over/rsp_under。新增150域单个粘滞错误寄存器，经单bit CDC到125并纳入首错，平台复位清除；禁止直接组合跨域或把多bit错误码逐位同步。所有数据及DDR信用协议保持。

同时，500 MHz窗错误与旧流水v[5]同沿时，错误结果优先，并明确清pilot_audit_valid，避免产生“本沿已失败但仍标audit有效”。此前已经输出的audit及后端normal/FFT audit仍是局部调试数据；必须与最终frame/generation/error/estimate_valid共同解释，失败帧的部分audit不能作为功能成功证据。原顶层不将这些audit作为正式算法输出。

入口队列静态状态表：

| 原count | push/pop | 处理后count与头尾 |
|---|---|---|
| 0 | 1/0 | 1，head取新记录 |
| 1 | 0/1 | 0 |
| 1 | 1/0 | 2，新记录写tail，head保持 |
| 1 | 1/1 | 1，新记录替换head |
| 2 | 0/1 | 1，原tail移到head |
| 任意合法count | 0/0 | 记录与count保持 |

count=0不允许pop，count=2不允许push（满转非满时保守空一拍）；稳态count=1可每拍同时出入。last写入队列即关闭本帧入口，因此最后记录不会让新一帧提前挤入。取消清队列且对外s_ready/m_valid被抑制；致命错误同沿若已被上游接受的记录属于失败整帧，随队列丢弃，不计为成功输出。head仅在弹出或空槽写入时改变，阻塞期间所有225位稳定。

后端寄存器result_valid=1时不允许join；消费该结果后下一拍才允许重新接纳，两个核心结果同时消费，所有499位由同一沿锁存。abort与join同拍时abort优先并清valid，不泄露旧帧。第一、二旋转继续分别S16舍入饱和；坐标和正式SFO步长端口未改，3.58秒SFO处理保护与约8.59秒顶层阶段保护也未放宽。

## 8. 尚存隐患与由用户安排的后续验证依据

- 持续流：当前确定不满足连续500 MS/s。先改存储访问/多会话调度架构并取得真实NI带宽/最大响应空隙，随后才有持续流验收的前提；有限离线功能测试不能消除此缺口。
- 时序：新增寄存边界解决原路径结构；150 MHz绝对差/模式判定、全链高扇出错误/使能、500 MHz ROM银行选择、蝶形/累加与SFO内部路径仍须后续检查真实网表和实现时序。不得降低125/150/500 MHz要求、增加虚假false path或减少精度来通过。
- CDC与复位：旧182条Warning不因本轮修改自动关闭；新增桥错误单bit同步也需纳入后续结构报告。NI提供三个时钟的实际关系、启动停止次序及全局reset宽度应落实；本轮未修改XDC去掩盖这些问题。
- 外部DDR永久不响应：当前有意保留信用并等待排空；CAPTURE及取消排空无可强制丢信用的本地超时。必须由NI协调处理/全局reset，不能把无限等待当正常性能，更不能直接清信用后复用旧tag。

- 同拍错误优先级按第10节固定，外部cancel优先；根级可能报告通用algorithm错误，分段诊断独立保留。这是明确的接口选择，不声称同拍事件存在可辨认的物理先后。
