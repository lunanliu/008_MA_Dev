## 3. 第一项设计：一份帧描述与一张存储生命周期表
输入只需真实原始IQ、合法配置及传输握手；不能让Host提供真实TO、CFO、SFO答案以代替RTL估计。frame_id和generation由系统实际捕获/会话管理产生。
统一描述符至少说明：帧与generation、原始采样绝对位置、原始数据基址与长度、前导位置、有效/保护范围、粗CFO及单位/定点格式、两级SFO步长与原点、当前处理版本、错误与有效状态。
原始数据在前端判定完成前就要保存，保证能回读发现的前导。明确预触发保留长度、检测延迟、环形覆盖条件及捕获不到时的回收方式。

## 4. 冻结处理顺序和接口
先依据现有算法合同和论文链路画一张人类可读的数据流图：原始采样捕获与同步前端 → 首次SFO估计所需训练支路（包括既有局部粗CFO相位补偿）→ 第一次SFO重采样 → 残余SFO估计 → 第二次SFO重采样 → 全帧粗CFO相位补偿 → 残余CFO估计 → 最终相位补偿。
SFO改变采样位置；CFO是复数相位旋转，不是重采样。不能因为术语混用新增一次重采样或改算法顺序。
前端288位结果不能直接接SFO的188位帧描述+96位CFO+96位精定时记录。需要明确epoch与generation、64位绝对TO与局部32位坐标、质量/状态字段的映射及握手配对。
SFO输出到CFO需要稳定的、与同一frame/generation原子绑定的两级步长、raw_origin及CFO配置；不能通过debug信号或参考答案拼配置。核实整数Hz到CFO定点Hz的转换、样点坐标映射、初始相位和每拍4路的相位连续性。
原始样点编号、当前输出编号、时钟周期号必须分清；500 MS/s数学采样率与150 MHz逻辑时钟不混用。
所有数据与描述符定义ready/valid、长度、last、错误、取消、重复启动和复位后重新接收条件。板上能够观察每段输入/输出计数、溢出/下溢、首错、FIFO占用及处理阶段。

## 5. 时钟和跨域
沿用已验证核的真实125/150/500 MHz边界进行首版集成，不为统一外观强行改成150 MHz。必须核对每条跨域数据、描述符、配置、复位释放和busy/ack。
明确时钟来源由NI平台还是RTL时钟管理器负责；同一个时钟只设一个生成责任方。若RTL生成则实体化对应器件原语/IP、locked与复位释放，并交对应约束；若NI提供则交准确端口和接线/启动顺序。不要把500 MHz时钟当成需要放进500 MHz SCTL的承诺。
XPM FIFO复位遵守其实际同步语义；异步assert、同步release与多域握手分别检查。不得用大范围false path掩盖不完整CDC。综合时序估计不等于NI最终布线时序闭合。

## 6. 最小验证计划：按风险验证新增部分
默认最多五组短检查，不安排几十/上百组扫参，也不重跑T10那种全帧超长行为仿真。每组写清新增风险、输入来源、参考对象、必须检查的输出及预计墙钟时间。
1. 静态源身份、真实XPR/top/IP/约束、全设计编译/展开，以及Wrapper接口核对。
2. 共享缓存和调度的独立短TB：写读一致、地址环回、长度/首尾、帧与generation隔离、覆盖/释放、受限背压和取消。用序号数据验证无丢失/重复/乱序。
3. 描述符/时钟跨域/复位和相位坐标适配的定向短TB；只测实际新增或修复的边界。
4. 算法衔接的已有向量片段测试：通常2～4符号；需要74条观测的估计器保留真实74条，不用删减数学观测来伪造短测。可在合法边界回放已发布中间向量或用接口服务模型隔离慢核，但报告准确区分真实核、替身及未覆盖范围，生产综合中不得包含测试替身。
5. 一次短顶层控制冒烟或等效的分段闭环连接检查，加一次真实完整核心综合/网表导出及资源/时钟报告。顶层不得有未实现算法黑盒、悬空关键控制或常量参考结果。
以上按缺口合并实施，同源已通过项目不重复125/150 MHz仿真。首个错误立即保留证据定位，只重跑受影响的失败阶段。新增测试必须对应一个未覆盖的具体风险。
默认不启动长帧、广泛参数扫参或额外布局布线优化循环。若完整真实核短功能测试受固定算法长度限制，明确保留该限制，用部件/接口证据加板测计划收尾，不声称已完成全帧RTL或持续吞吐验收。

## 7. 给用户的可预期结果和板测方法
整理既有证据支持的输入范围表：SFO/CFO、SNR、定时、帧结构、幅度/量化和信道条件。分开列论文假设、现有分模块测得结果、整链预期、新短测结果和待板测项。
精度说明必须明确比较谁与谁：RTL对定点参考、定点对浮点、补偿后对无偏差参考。EVM在FFT窗口与全时域分开；已有SFO的FFT窗口<-45dB门槛只在对应数据/参考口径继承，不自动变成含噪全链绝对EVM要求。
给出至少一套可直接上板喂入的波形、设置值、预期中间记录、最终输出比较方法。Host不注入真值估计。原始与各级补偿数据的导出量可选择，默认不以大规模debug拖慢正式数据口。
板测步骤包含：时钟/复位→配置→装载或采集原始IQ→触发处理→读回→比较→统计接受样点、输出样点、stall/overflow及整帧时间。
分别定义有限长度离线DDR回放和连续流500 MS/s目标。4×150 MHz只表示600 MS/s端口峰值，不是持续速率证据；需要总帧处理预算、真实读写带宽、两次/多次访问成本。最终真实吞吐由用户板测确认。
