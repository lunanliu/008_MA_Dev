## 失败分级和处理

| 情况 | 本次处理 | 结论边界 |
|---|---|---|
| 普通调用/API/字段/解析问题 | Luna 版本化修复；保留成功阶段，只补缺项 | 未验证的项目仍未验证 |
| 可选状态副本或回执格式失败 | 本地保留原始数据，离线修正 | 不否定已完成计算，也不能只凭 exit 0 判 PASS |
| 科学身份、真实 CDC/Gray 或功能不符 | 保留证据，交 Astra 判定受影响设计 | 不改预期值、不增加豁免或伪造 PASS |
| 真实时序负裕量 | 记录 OPEN，进入 RTL 设计修复和受影响验证 | 报告完整不等于时序闭合 |
| 安全消息审批拒绝 | 停止被拒发送并说明实际原因，禁止重试或改目的地/通道规避 | 不把本地报告 PASS 写成通信 PASS；独立获准本地工作按本次 grant 继续 |
| 实际槽冲突、硬截止、明确内存分配失败或证实停滞 | 依已审监管收尾，仅处理所属 PID+creation 进程树 | 用户 GUI/无关编译器不能按名称一律终止或拒绝；资源仍须核算 |

原任务书把“完整资料外发预检成功”与“本地报告启动”绑定的条文，由本次补充替代。平台审批本身保持有效，之前明确拒绝的消息不重试。此分离不构成消息批准，也不代替科学预检、中央资源准入或安全检查；初次本地报告按最新用户指令先执行，随后实际尝试交回，并分别记录两者结果。
