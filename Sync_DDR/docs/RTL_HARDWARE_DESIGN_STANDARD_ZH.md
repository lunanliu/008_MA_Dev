# RTL 硬件设计前置规范

版本：2026-09-17。依据：用户在总管家任务中明确要求，把真实硬件的频率、吞吐、资源、竞争关系与实现可行性放在设计阶段，并写入所有相关 Agent 可读的文档。

## 1. 必须遵守的设计次序

**指标与约束 → 硬件架构及每拍预算 → 设计自审 → RTL实现 → 受影响的短验证和早期综合 → 集成 → 相应层级验收。**

功能正确是必要条件；它不能替代可综合性、时序、资源、持续吞吐或跨域正确性。不得先按软件式逻辑直接连接信号，再把已可预见的长组合链、回压、高扇出或存储冲突留给最终工具/板测处理。已有实现与规格冲突时，先修订受影响的架构，不把有缺口的模块当作合格基础继续扩大集成。

本规范要求设计依据，不要求多造审批流程。可以直接在已有任务书、模块说明或代码附近记录；已有合同只引用一次，微小修改只记录受影响项。缺失关键指标时先核查已有用户要求和证据，只对确实无法确定且影响设计的项目询问；其他独立的已授权工作继续。

## 2. 编码前的最小设计记录

以下项目可合并为一页表格；简单模块可用简短段落表达，但不能留出影响实现的空白。

| 项目 | 必须明确的内容 |
|---|---|
| 目标与边界 | 器件、封装、速度等级、工具版本、模块职责、真实输入输出、允许的数值/算法范围 |
| 时钟与接口 | 每个域的频率、周期、同步/异步关系、时钟来源、端口时序；相关 IP 的配置和约束 |
| 吞吐与延迟 | 持续速率及单位、每拍有效样本/字节、启动间隔、首结果延迟、每帧服务周期、帧间空隙、允许背压 |
| 存储与资源 | 数据生命周期、容量/深度/端口、每帧读写量、仲裁开销、DDR服务假设；LUT/FF/DSP/BRAM/URAM预算及平台外壳余量 |
| 电路结构 | 各流水级的运算和寄存器边界、最长数据/地址/控制/回压候选路径、扇出与布局风险及拆分方案 |
| 安全与一致性 | CDC、复位、取消/重启、帧/epoch归属、同时事件优先级和存储所有权 |
| 验证依据 | 重用证据的具体版本/器件/层级；新增风险对应的短测试、早期综合和后续实现检查；尚未验证项 |

估算要写依据与假设，后续用真实报告校正；不能伪造精确数值。器件资源预算与运行工具的主机内存预算分别管理。

## 3. 每拍时间预算与流水结构

- 先换算时钟周期。例如125、150、500 MHz分别为8、约6.667、2 ns。这些是整个时序路径的周期，不是可全部分配给组合逻辑的时间。
- 同域寄存器间的初步规划需扣除时钟到输出、目的寄存器/RAM建立时间、时钟不确定度，并预留连线与偏斜影响；最终以对应器件和约束的静态时序分析为准。跨域不能套用单域周期相减。
- 明确哪一拍做比较、差值/绝对值、乘加、优先选择、索引映射、基址相加和RAM读写；禁止默认把多项复杂运算串在一拍。对常量运算可做有位宽、符号、溢出、舍入与边界证明的等价化简。
- 高速存储和DSP路径审查其输入、输出及内部寄存器配置。流水级数由路径预算和接口合同决定，不能仅按代码行数或“算子看起来简单”决定。
- 流水后同时对齐数据、valid、frame/epoch、index、last、错误、取消及配置快照；暂停、复位和清空策略也必须一致。增加若干拍延迟不必降低稳态吞吐，关键是启动间隔和缓冲容量。

## 4. 握手、扇出和物理可实现性

- 明确每条 ready/valid 是组合还是寄存输出，追踪跨模块前向与反向传播到真实寄存器/RAM端点。不得有组合握手环；不得因模块分别通过功能测试就假定连接后的长回压链合格。
- 需要切断回压时采用有容量依据的弹性寄存、skid buffer或FIFO，保证回压生效前额外到达的数据有位置。禁止只寄存ready而不调整容量和接受条件；背压时保持已有效负载，正确处理同时入出及满空边界。
- 结果判定、复杂错误译码或宽比较不应未经预算直接控制远端ready/RAM使能；考虑寄存判定、局部状态和解耦缓冲，同时证明握手与异常语义保持。
- 在设计时列出潜在高扇出使能、复位、广播控制、地址和选择信号，考虑逻辑局部性、bank/区域、SLR跨度和跨模块距离。根据报告区分逻辑过深、扇出/连线、拥塞或约束问题，不把所有失败归为同一原因。
- 局部控制复制和流水化必须保持相同周期/复位/使能语义，计入FF、存储与布线成本。不要滥用MAX_FANOUT、DONT_TOUCH或布局约束代替架构分析；必要的物理约束须说明依据。

## 5. 持续吞吐、缓存与器件资源

- 输入需求、核心服务能力、输出消耗与DDR读写使用同一单位核算；写出一帧各阶段工作量、启动间隔、多遍处理、帧间空隙及最坏允许服务间断。
- “并行路数×频率”只给端口峰值，不能覆盖仲裁、共享FFT/乘法器、背压、DDR响应和重复读写。持续吞吐承诺须有接受样本/周期、丢失/重复/重排、队列水位和最坏服务间隔证据。
- 缓存必须有生命周期和所有权，核算同时驻留的数据、端口冲突及读写次数；不可简单叠加整帧缓存，也不可让FIFO无限吸收平均服务率不足。
- 明确RAM读延迟、读写同址行为、bank访问和数据版本；释放、回放、重写与新请求同时出现时有确定规则。
- 先估算LUT/FF/DSP/BRAM/URAM与关键互连的余量，包括外围控制、CDC、弹性缓冲及目标平台外壳；核心能放下不等于加入NI/DDR外壳后仍合格。

## 6. CDC、复位与竞争关系

- 标出每条实际跨域连接，按单比特状态、脉冲、计数/指针、描述符和数据流分别选择同步结构。多比特相关数据不得逐位同步后假设一致，应通过握手稳定窗口或合适FIFO等机制原子传递。
- Gray指针必须有适用的计数/编码/源寄存结构及目标同步器；逻辑上相邻值单比特变化不替代有效max_delay/bus_skew等物理约束及报告核实。复位跳变、旧epoch和新数据混合须单独处理。
- 定义各域复位释放和FIFO恢复完成条件；复位/取消时应清空或隔离旧事务，直到合同规定的恢复握手成立。不得用不受控组合逻辑生成时钟或异步控制。
- 明确同拍请求与完成、释放与回放、取消与输出有效、旧响应与新帧、同时读写/满空切换的优先级与所有权。同步设计也存在协议竞争，不能因使用时钟就忽略。
- 审查非预期锁存、多驱动、组合环、毛刺敏感异步输入和跨域重汇合；仿真调度巧合不能充当硬件顺序保证。

## 7. 将工具反馈提前，但保持证据层级

结构成形后，在既有授权和资源预算内，尽早对高速新核、改动的算术/地址路径及新增握手/存储边界做真实约束下的综合。不能等待全部长仿真或上板后才首次确认基本时序可行性。布局布线检查在相应阶段和授权范围内安排；本规范本身不启动新实验。

审查应覆盖真实source set、top、器件、IP参数、时钟、未约束路径、适用I/O、CDC和例外约束，以及关键路径起终点、级数、扇出、逻辑/连线延迟和资源。既看数据路径，也看ready、enable、reset、地址路径。不要只修一条最差路径就宣布所有失败端点关闭。

分别标注：数值模型、RTL行为、接口短测、IP OOC、完整核心综合时序估计、布局布线setup/hold、持续吞吐、平台编译和板测。仿真按2 ns激励不证明500 MHz物理时序；IP孤立实现通过不替代外围逻辑和完整设计验收。当前级别未验证就写未验证，不能升级表述。

禁止用无依据false_path、多周期、过宽异步分组、降频、降精度或更换验收口径来掩盖失败。合法例外必须与真实电路和协议一致；真实规格变更需明确依据并遵循用户授权。

设计审查能提前排除可预见风险，不能保证首次最终布线零问题。实测暴露新物理限制时应反馈架构并针对性修正；纯日志、格式或消息交接故障不重跑成功计算，成功阶段和失败证据均保留。

## 8. Sync OTA当前修复必须体现的设计依据

本节是2026-09-17现有证据的教训，不是修复已完成的声明。

- 150 MHz：已观察CFO结果差值/绝对值/一致性判定经多级ready到SFO输出缓存ENARDEN的35级路径。修复前说明判定的等价化简、寄存/缓冲边界、接受条件和额外在途数据容量，证明错误/取消/帧边界不变。
- 500 MHz：已观察CFO FFT输出索引到导频选择、系数寻址和ROM使能的路径。明确逐拍拆分和数据/索引/valid/取消对齐，证明目标启动间隔保持。
- 以上是已定位的两条最差路径，不能替代所有失败端点的复核；当前不能未经报告便认定高扇出是全部或已证明的根因。
- 保留125/150/500 MHz及已冻结算法、位宽/舍入、接口目标。报告恢复和实际RTL修复分开；真正RTL变化才安排受影响短等价、握手验证及新的核心综合。
- 现有原三个工程只读、原Astra/Luna配对、资源准入、手工LabVIEW交付边界继续适用。不得借此自动启动布局布线、NI编译、板测或旧暂停作业。

## 9. Agent分工与执行约束

设计者（Astra）负责先写清指标与架构、检查预算和接口物理边界，再冻结RTL及验证范围；执行者（Luna）核对实际输入/工具/约束并如实保留结果，自修执行问题时不得改变电路与验收含义；总管家核对范围、资源和交接，不代替科学复核。

本规范由用户直接要求建立。它不降低或改写安全审批、具体披露授权、原生资源准入、停止/恢复规则，也不为每条设计判断新增用户审批。没有足够依据支持的硬件设计不得作为合格设计交付；已授权且无依赖的准备与修复继续推进。
