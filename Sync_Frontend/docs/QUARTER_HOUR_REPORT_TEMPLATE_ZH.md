## 填写规则

- 仅正在工作的线程独立报告：总管家处理协调，Astra进行设计/诊断/复核，Luna执行或监控运行中的实验，均算工作。Astra派单后已结束本轮、Luna无作业等待派单、等待用户决定及其它空闲均停报；不能因同项目仍有人工作就让所有线程报告。保持上述顺序和两张表，按职责增减行，末行之后不加内容。
- 时间含时区；只报已核实进展。无新结果/无作业明确写出；未核实不等于空闲。预计用范围，不能估计注明原因；阶段已用时、预计总时长、整体剩余分开。
- PID/哈希/完整路径存执行记录，异常才展开；资源数按真实准入。报告优先读取已发布状态并注明采样时间，不为报表重做实验或跨线程索要回执。每个线程独占 reports/operations/thread_reports/<thread_id>/report_clock.json，记录 work_state/work_started_at/last_report_at/next_due_at/automation_id；本线程同一窗口只报一次，不能用另一线程的报告去重。旧Luna时钟仅供首次迁移读取，保留原文件。
- 用get_usage_limits读当前账户周配额：按windowDurationMins=10080识别周窗口，优先rateLimitsByLimitId；已用=usedPercent，剩余=100-已用（限0到100），重置时间换算时区。不同桶分别显示，不混用5小时窗口；缺失写暂不可取得。账户共享，各线程显示的是同一账户用量，不能相加或归因给本线程；不统计token、模型调用量或15分钟增量。
- 每个线程开工时记录WORKING和开始时间，通过automation_update启用自己的15分钟定时器；结束本轮、进入空闲/等待或用户暂停前先记IDLE/PAUSED并暂停自己的定时器，再final。新工作从本次开工计时，不继承空闲时长；不足15分钟直接做正常结束回复，无须补发定时报。映射见reports/operations/single_task_control.json；后续线程开工时配置同样规则，不创建新的开发线程。
- 定时器只服务正在进行的工作，不作为空闲线程的唤醒器。过期触发到达已空闲线程时暂停并静默结束；不发空闲报告、不启动工作、不传递接力消息、不改模型/强度/Fast。应用离线或调度延迟导致漏报时，仅在实际恢复工作后说明一次，不编造准时报时记录。
