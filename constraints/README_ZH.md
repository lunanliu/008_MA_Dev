# 约束的用途和边界

当前工程启用`t10_root_clocks.xdc`，声明125/150/500 MHz三个核心输入时钟。它足以说明项目时钟意图，但不是完整平台时序预算。

`reference_synth016/`原样保留旧核心综合的两份必要约束来源，便于人类后续接手物理实现：

- `production_clocks.xdc`除时钟外，包含旧OOC时钟位置及排除外部I/O时序的false path。
- `production_crossing_constraints.tcl`包含六组时钟跨域的最大数据延迟、总线偏斜和输入时钟标注；它还依赖旧运行目录变量，属于综合后执行的原生Tcl。

这两份历史文件没有自动加入当前有效约束集。不能把旧OOC外部I/O排除搬到板级设计后声称接口时序通过。后续综合/实现前，需要结合FLGB目标、当前顶层和XPM生成约束审查并迁移这些意图，明确外部时序预算。本轮仅建立项目和核对身份，不运行该物理验收。

Xilinx IP自身的生成约束随新目标IP输出生成。不要拿旧FLGC生成目录中的XDC/DCP代替它们。
