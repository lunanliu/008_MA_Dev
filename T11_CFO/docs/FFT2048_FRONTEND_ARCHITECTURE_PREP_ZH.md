# FFT2048/导频前端：进入实现前的结构预算

2026-09-14。前置门槛：74点后端已经由RTL计算归一化、FFT256质量、相位拟合和模式，38完整结果及控制边界通过；具体见reports/BACKEND006R1_REVIEW_20260914。前端尚未实现，本文是结构预算，不是综合、时序或吞吐验收。

## 冻结的数学输入输出

对粗CFO补偿后的S16/F15波形，窗口首样本25984+m*17920，m=0..73；每窗口2048点。乘64转换到S26/F21，执行11级radix2 DIT，每级RNE除2并S26饱和；twiddle S18/F17，正1裁到131071。

实际CSV含60680行、74符号（0,7,...511）、每符号820导频。k顺序为2,4,...820，再-820,-818,...-2；自然FFT bin为2..820偶数，再1228..2046偶数。按原公式c=quant(conj(P)*exp(j*2*pi*k*128/2048)*2^17,S18)。F与c复乘后RNE除2^17，饱和S28，再对820个导频求和到S38，送后端z。禁止把P先量化成Q15后再生成c来替代原系数。

## 服务周期约束

每帧1336320点，按500MS/s是2.67264ms，74个FFT窗口。相邻导频窗口平均间隔17920/500MHz=35.84us。现有FFT256是一蝶形5拍，直接扩为2048后，即使500MHz，纯蝶形也需11264*5/500MHz=112.64us，不能据此支持规定帧处理量。

拟采用迭代FFT、蝶形流水后每拍发出一个蝶形：11级共11264次；算上2048点装载、2048点自然序输出及级间排空，目标服务约15400到15500个500MHz周期，即30.8到31us。74窗口纯服务约2.28到2.29ms，落在2.67264ms帧预算内。这只是周期算术和目标，实际发射间隔、排空、背压、CDC、地址冲突和500MHz实现时序必须分别验证。

内部粗补偿路径可能按4路150MHz的600MS/s突发，窗口到达间隔可短至29.87us。上述前端不能无条件声称吸收无限600MS/s连续突发；必须以粗补偿缓存发布水位、窗口排队和跨帧占用证明真实输入包络。暂时的单帧FFT排队不等于数据已丢，但不能凭平均处理量跳过缓存寿命证明。

## 拟采用的存储与运算结构

两个数据bank，各1024x52位；bank为11位FFT地址的异或，row为低10位。蝶形两地址只差一级的一个bit，必落在不同bank，每bank每拍一读一写；流水回写延迟后仍需在级末排空，禁止读到尚未完成的上一级值。装载采用11位反序，输出自然序。先用整数周期模型验证全部地址唯一覆盖、bank冲突与读写依赖，再交原生RTL验证。

26x18实乘、45位复乘加减、RNE移17、29位蝶形加减及RNE/2/S26夹紧；具体流水分级要在综合和500MHz约束下评估。不能把代码中的4个实乘直接当成最终DSP数。

系数若全部确属8个固定PSK码，可用每导频3位索引加8项精确S18复数表，约182040比特索引，减少直接存60680x36位的开销。但必须先逐项核对已发布MATLAB的c是否满足该集合且不同case一致；现在不把这一点当成已验证事实。

前端500MHz和后端150MHz之间还需要带frame/generation/window-index/last的CDC记录；当前后端单时钟验证不包含这个CDC。存储、资源、全帧及吞吐证据均保持独立。
