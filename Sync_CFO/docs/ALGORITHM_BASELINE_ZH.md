# CFO整链最终算法交付（2026-09-13）

结论：主算法与全部具体数值参数已确定，完整MATLAB黄金模型、自定义有限字长模型和独立复核已完成。主方案在9个冻结单LoS条件、每条件10个新随机种子上全部满足预先采用的质量门槛，并在2个实际T10 bit-true输出上完成接入核验。当前交付不是T11/T12/T13原任务书的正式RTL阶段PASS；直接新增两个独立URAM全帧bank会违反资源硬上限，存储复用/外部存储与物理吞吐仍待硬件集成证明。本轮不再启动实验。

## 先解释信号从哪里来、如何估计
两次SFO后输出仍可能含较大粗CFO。处理顺序固定为：T10第二次SFO输出→按原粗估计旋转整帧→用导频估计residual CFO→再次旋转整帧。CFO补偿通过乘一个反向旋转的复数完成，不改变采样时刻；SFO补偿才改变采样位置。

可以把复数信号看成一根随时间转动的指针。每个导频的发送值已知，先除去/共轭消除导频本身，再消除A128固定窗口带来的已知相位，就得到直达路径的复数观测。CFO使这些指针随时间持续转动；量出每秒转了多少圈，就是频率偏差。

本实现从74个导频OFDM符号各取2048点FFT，选820个已知导频并求和，形成74个复数z_m。间隔Δt=17920/500000000秒。先做256点FFT检查是否存在可信且不明显混淆的频率峰，再对74个相位展开并拟合直线：phase_m≈常相位+2π*f_res*t_m。斜率/(2π)给Hz，截距是常相位。主实现采用此相位拟合精估计，保留带状态标记的FFT降级和拒绝路径。

DTP是“时延随观测时间变化”的二维表示；在已知LoS时延位置取复数值，就有上述随时间变化的观测。对时间维做FFT可得到DDP的多普勒维。DTP时延轨迹的斜率反映SFO导致的时延漂移，轨迹截距是初始时延/定时位置；不能把该截距当CFO。也不能只保留DTP功率后再从其截距恢复CFO，因为频率所需的相位信息已丢失。当前实现假定LoS已对齐，只提取固定时延处的观测，没有实现任意时延搜索或通用LoS身份鉴别。

## T10输入与真值
T10保存输入可以复用，且原始CFO并非未记录：两帧注入physical CFO=100000Hz，frame6006保存粗估计99000Hz。两次SFO改变了输出与原始采样坐标的对应关系，所以先用描述符构造qRaw=origin+ratio*n，再作粗相位旋转。raw nominal Hz与physical Hz必须按原波形生成定义换算，不能直接用100000−99000宣称最终剩余恰好1000Hz。

本批另构造独立可控输入，将residualSFO/TO均设为0，单独验证CFO算法。真实T10输出保留它已有的噪声和定点重采样畸变，用于验证接入；两类证据分列。没有在本轮重新独立测量T10输出剩余SFO和TO，也不把设为0的合成条件当实际T10三offset闭环证明。

## RTL方案：计算可行性与实际存储限制
主结构采用两个独立4lane、目标150MHz/II1旋转通道。每通道每样本4个实乘、每周期16个，两通道共32个并行实乘；这不是综合后的DSP数量。主ROM每通道1024×32=32768bit，B为4096×36=147456bit；4lane每拍需要4个地址，若存储只有2个读口，需复制两份。两旋转通道合计主ROM逻辑容量131072bit、B为589824bit，物理RAM打包/布线未测，不能只算单读口表大小。

74个2048FFT前端不能漏算。窗口满速输入时起点相隔4480个150MHz周期；每拍单蝶形的迭代2048FFT需11264蝶形周期/窗口，赶不上，故应使用输入II1流式FFT或同等吞吐并行结构。后端FFT256是1024蝶形操作，74点24轮迭代CORDIC为1776微旋转，可用迭代器共享，不必复制到4个全采样lane。窗口缓存、FFT流水延迟、分帧配置与尾部调度需后续验证。

按最坏−150ppm输出需求500.075011MS/s，两个旋转通道各需≥83.34584%平均有效服务。单个4lane150MHz核承担两遍需166.69%，不能成立。最终回放一帧需2.2272ms；双bank条件下，估计尾部+参数装载+最终回放停顿合计须≤66755.8656周期，即445.039us。计划估计尾部30000周期、累计停顿20000周期，仍是待实现的预算。两个bank读写数据平均需4.0006GB/s、同时峰值4.8GB/s；FIFO还必须约束连续停顿和在途信用，不能只报平均吞吐。

**直接新增两个独立URAM全帧bank的方案被资源门否决。** 逻辑数据10.1953MiB；按项目4096×72bit几何和128bit拍，单帧164URAM、双帧328URAM。T10 SYNTH013已有552URAM，叠加880/960=91.67%，超过T00硬上限672块，超出208块。即使把剩余URAM与BRAM按理想位数混用，当前硬上限内只有9,918,720bytes，少于所需10,690,560bytes，尚未计CFO辅助缓存。因此不能宣称简单追加缓存后可在当前资源门内落片。

后续硬件路线必须是证明已有帧存储的寿命复用/端口调度，或提供独立外部存储及上述最坏服务能力。当前未冻结T10→CFO的共享bank所有权日程，也没有外存控制器实测，属于明确未闭合项。保留16bit数据和完整帧几何，不通过暗改字长、丢点或缩短帧满足资源。最终出口若只有4lane125MHz，容量500MS/s仍不足以持续接收负SFO最坏需求；需要满足已声明速率与突发条件的接口。CFO算法验收不意味着这一整机边界已解决。
